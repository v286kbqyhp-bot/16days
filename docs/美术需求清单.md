# 守望题材战棋美术需求清单

玩家在边境要塞为小队配装，出征保护水晶采集器，战后在结算界面缴税，再回营用余下的粉尘培养小队。第一轮建议以一张 8×8 森林棋盘和一次完整出征为交付范围。程序和美术合计约 10 天，由一人和一个 agent 完成。

**制作约定** · 下方复选框是待交付项。数量写「待定」的项目依对应专项策划排产。界面层级、点击步骤和复用方式是首版交互方案，画面、按键映射和具体素材仍按作者确认的方案执行。各章节中的「首版」是制作优先级。

## 1. 玩家角色

固定三名队员。装备不足时可少于三人出征。姓名、身份、最终模型和外观待定。每人各交一套盘面形象和营地识别图，营地识别图可从同一模型取图。

### 队员 1

- [ ] 盘面形象 1 套、营地识别图 1 张。
- [ ] 待机、移动、基础攻击各 1 段。首个三渲二样片先用本角色的一段自带攻击。
- [ ] 受击、濒死、特殊治疗后恢复站立各 1 种可辨反馈。

### 队员 2

- [ ] 盘面形象 1 套、营地识别图 1 张。
- [ ] 待机、移动、基础攻击各 1 段，按样片的机位、像素尺度和落格位置出图。
- [ ] 受击、濒死、特殊治疗后恢复站立各 1 种可辨反馈。

### 队员 3

- [ ] 盘面形象 1 套、营地识别图 1 张。
- [ ] 待机、移动、基础攻击各 1 段，按样片的机位、像素尺度和落格位置出图。
- [ ] 受击、濒死、特殊治疗后恢复站立各 1 种可辨反馈。

### 三人共用的动作与状态

- [ ] **动作时点。** 移动从原格到目标格，脚底对准格心。攻击记录蓄力、命中帧和收势。受击可复用已有动作或共用战斗反馈。濒死要有停留姿态，复起后按规则恢复可用行动。
- [ ] **治疗与空中。** 基础治疗复用一套反馈。特殊治疗触发复起。天空纹章进入首战时，增加空中状态表现和地面占格定位。
- [ ] **换装。** 三人都能换武器。首版建议用装备图标与攻击反馈区分武器，角色保留固定形象。手持模型随换装变化及特殊握姿的动画量等武器清单确定。
- [ ] **朝向。** 样片先交一个朝向。正式朝向数在棋盘内测试上下左右攻击后确定。确认哪些动作可镜像、哪些需要单独渲染。

## 2. 地精

首战建议先覆盖一种基础地精。出场只数、额外类型、远近程技能、飞行种和死亡效果等 [地精专项](design/地精设计文档.md)确定。

- [ ] 基础地精盘面形象 1 套。与三名队员、采集器的轮廓可区分。
- [ ] 待机、移动、基础攻击、受击、死亡或退场各 1 种表现。攻击的实际命中时点交给程序对接。
- [ ] 两种开场能用同一形象。地精已在场时直接出现在对应格，预告钻出时先标格，再按规则出现。
- [ ] 钻出成功、被阻挡及阻挡伤害可区分。被阻挡后的地精状态与波次待战斗策划确定。
- [ ] 死亡后能看出地精退场且格子已释放。掉落时复用实际物品图标。

## 3. 水晶采集器

准备 **1 款可重复部署的采集器**。实际台数、位置及附加目标由关卡配置决定。

- [ ] 基础形象、工作中、采集完成、被毁四种盘面表现。基础与工作中可共用模型。
- [ ] 采集进度、生命变化和受击反馈，能对回具体采集器。被毁后保留明确的结果表现，并在结算说明收益变化。
- [ ] 可选短特效为采集完成与晶屑。优先交工作中、完成和被毁的稳定状态。
- [ ] 确认采集器在固定机位下的锚点和占格轮廓，检查前后相邻单位及攻击标记是否被挡住。

## 4. 战场与地形

首版建议 **1 张森林场景、1 套 8×8 棋盘表现**。地形按首战地图采用的种类排序，其余列项随关卡接入。具体地图见 [关卡专项](design/关卡设计文档.md)。

- [ ] **场景布景。** 确定固定机位和一组可复用的森林素材，划清盘面、可点击地形和场边布景。树冠和其它布景不能挡住棋盘、单位或地精预告。场上水晶与结算用整晶保持形态关联。
- [ ] **普通地。** 基础地表和完整格界。石块破碎后可复用这套地表。
- [ ] **草地。** 未点燃与燃烧两种外观，可识别格内持续火焰。离开火格后仍在燃烧的单位由单位状态标记说明。
- [ ] **水地。** 明确水域格界，能表现陆地单位潮湿和燃烧解除。空中单位占格仍可读。
- [ ] **石地。** 识别阻挡和碰撞格。第一次碰撞有反馈，第二次碎裂并变回普通地。是否独立画受损外观按工时安排。
- [ ] **沙地。** 沙地和影响攻击的沙尘状态可区分。沙尘出现时保留格界和单位位置。
- [ ] **地洞。** 能认出禁入边界和坠落位置，并与出怪预告区分。
- [ ] **场上道具。** 有地图宝箱的关卡需要可辨识的宝箱形态和开启结果。附加任务涉及其它特殊装置时，按关卡逐项补。

### 场景素材候选

- **Ultimate Stylized Nature Pack，CC0。** Quaternius 的自然素材，含树、灌木、草和岩石，提供纹理与法线贴图。适合先和同作者的角色样片对照。 [作者预览](https://quaternius.com/packs/ultimatestylizednature.html)
- **KayKit Forest Nature Pack，CC0。** 免费版含树、灌木、岩石和草，模型共用渐变图集。可对照较简洁的色块和树冠轮廓。 [作者预览](https://kaylousberg.itch.io/kaykit-forest)

## 5. 场景外的物品与图标

同一物品优先在营地、商店、战利品和结算使用同一张图标。尺寸、透明边距和缩放方式在首个界面样式确认后统一。

- [ ] **资源图标。** 整晶、粉尘、强化硬币各 1 枚图标。整晶和粉尘同源，靠轮廓区分，计税数量统一为克。硬币的单位用枚。
- [ ] **武器。** 每件在首版出现的武器 1 张图标。覆盖基础装备、图纸解锁和制作成品的识别关系。种类和数量随 [武器专项](design/武器设计文档.md)。
- [ ] **符文。** 每个首版符文 1 张图标，另做空槽、装配、已强化和锁定的共用状态。卸下、清除与硬币返还由共用交互反馈表达。
- [ ] **纹章。** 每个首版纹章 1 张图标。普通和传奇有共用区分方式，覆盖装备、锁定、失去和赎回。同一枚纹章贯穿营地和结算。具体名单随 [纹章专项](design/纹章设计文档.md)。
- [ ] **奖励。** 图纸、实际出现的怪物素材和关卡宝箱图标。强化硬币复用上面的资源图标。奖励数量、掉落概率由规则取值。
- [ ] **治疗道具。** 先做治疗操作图标。策划确认消耗品后，再补药水图标和数量状态。

## 6. 棋盘标记与单位状态

- [ ] **点选与部署。** 普通格、指向格、选中角色、合法部署、已部署和不可部署。
- [ ] **移动与攻击。** 可移动范围、可选攻击目标、攻击方向和落点、位移方向与预览落点。目标或地形变化时，读得出当前有效预览。
- [ ] **敌方预告。** 攻击来源、方向、受影响格及出怪格。敌人被移动或击倒后，按规则刷新或清除对应预告。钻出点和地洞采用可区分的形状。
- [ ] **单位状态。** 生命、移动可用或已用、攻击或治疗可用或已用、濒死、燃烧、潮湿、沙尘阻攻和空中。图标仅随生效规则展示。
- [ ] **层级。** 观察同格的悬停、移动、受击预告、单位及地形状态能否共存。危险预告和状态在非动画时仍可读。重要状态组合形状和颜色区分。

## 7. 动效与战斗特效

先做规则所需的反馈。特效根据第一场实战的可读性和剩余工时追加。

- [ ] **首版动作反馈。** 直接命中、单位推拉、碰撞双方扣血、普通和特殊治疗、濒死与恢复、地精退场、采集器损毁。表现跟随实际结算事件。
- [ ] **首批增强特效。** 地精钻出及阻挡，推撞命中和短暂位移反馈，石块碎裂。先对齐格心和命中帧，再加细节。
- [ ] **后续特效。** 按实装地形做格内燃烧、灭火和潮湿、沙尘、坠落。采集完成可复用晶屑。武器技能、护盾及其它纹章效果按首版内容表增补。
- [ ] **验收。** 短效结束后仍能读到格子或单位实际状态。位移与生命变化和程序事件一致。特效叠加时攻击预告和出怪格保持清晰。

## 8. UI 导航与界面串联

营地有备战、商店、铁匠铺、搜刮小队四个入口。战斗包含部署和行动两个阶段。结算和缴税属于战果结算界面。营地构图、各入口点击后的面板与返回路径见 [营地场景设计](营地场景设计.md)。

**首次进入** → **营地** → **备战快览** → **确认出征** → **战斗部署** → **战斗行动** → **战果结算（含缴税或补税）** → **营地**

- **备战**打开装备快览和详细配装。**铁匠铺**共用一个入口，在内部切换制作与强化。**商店**和**搜刮小队**各有入口。查看详情或取消后回到发起位置，保留选择。
- **确认出征**是备战快览内的独立操作。检查未通过时停在快览并标明缺项。通过后锁定本次出征装备，进入部署。部署期间在允许格反复调整，确认部署后进入战斗行动。
- 战斗胜利、失败或提前回营都先进入独立的战果结算。在结算内缴税或补税，办完后进入营地。无力补税且没有可出售装备时，进入本局结束与重新开局入口。
- 暂停、设置、读档续玩、关卡选择和大地图属于待确认的独立入口。首版导航可按关卡配置进入首战，不需要先定大地图布局。

## 9. UI 开始与本局结束

- [ ] **首次进入。** 建议预留开始与退出入口。开始进入首个营地，退出正常关闭窗口。标题用最终确认的游戏名。
- [ ] **本局结束。** 显示本局结果和无法继续出征的原因。若选择重新开局，回到新一局营地。退出走共用退出处理。
- [ ] **基础引导。** 建议在第一次配装、部署和攻击预告处复用简短操作提示。引导的内容跟随当前可执行操作。

## 10. UI 营地主界面

- [ ] **需要做的场景内容。** 一张营地局部画面，第一眼能看见备战桌和三名队员，取景含侧边马车、部分兵营、厨房、锻造区与补给处，并能点到备战、商店、铁匠铺和搜刮小队。四周角楼、木栅、营门和木质防撞栏按营地实际布局择取入镜，当前粉尘与强化硬币。构图和站点外观见 [营地场景设计](营地场景设计.md)。
- [ ] **点营地入口。** 打开对应界面，返回时恢复同一处营地画面。进备战时先显示三名队员的装备快览，进其它站点时先显示该站点列表或空状态。
- [ ] **备战与确认出征。** 点击场景里的备战入口打开装备快览。完成检查后，玩家在快览里另点确认出征。校验失败时在快览标出缺项，通过后进入部署。
- [ ] **回营更新。** 缴税成功回营后，采集余额、装备锁定、纹章损失或奖励和商店刷新结果以实际数据更新。装备不足时仍能知道哪几名队员可出征。

## 11. UI 备战快览、配装与背包

- [ ] **装备快览。** 三名队员的参战状态、武器、纹章、符文和缺项一眼可见。点击槽位进入详细配装，改完回快览。确认出征与返回营地使用不同操作。

- [ ] **需要做的界面内容。** 角色选择、1 个武器槽、1 个纹章槽、所选武器的符文槽、物品列表和详情。主策划默认 2 个符文槽，实际按武器读取。支持空、已装备、被他人占用、锁定和已强化状态。
- [ ] **装备与卸下。** 点槽位看可选物品，确认后刷新队员装备和库存。选择被占用物品时显示当前持有者。卸下后槽位变空、物品回到可用列表。
- [ ] **符文操作。** 点空槽选择符文。显示装配费、付费拆卸与免费清除的不同结果。确认清除前说明符文会失去。拆卸已强化符文时显示返还的强化硬币。
- [ ] **返回。** 关闭物品详情回到同一队员与槽位。回营地主界面时显示已落地的变更。战斗中只显示锁定后的配装信息。

## 12. UI 商店与交易

商店使用纯 2D。正式流程从营地进入。先在 Godot 中做成可单独运行的商店场景，等营地布局确定后接入入口。

概念参考为 2026-11-26 生成的像素风商店图。左侧店主、后方杂货架和前景木柜台作为构图参考。图中八个商品格、材料陈列、价签金额和 24 g 余额均为示意。首版实际在售为两个符文商品位、一个普通纹章位和一个传奇纹章位。强化硬币的购买与消耗都在铁匠铺的强化界面处理。

2026-11-27，作者对比其他游戏与 UI 素材后，选择最初的[像素商店概念图](art/shop-reference.png)作为气质、色彩和构图参考，并明确要求结合游戏功能重新组织细节，在像素软件中按多个独立部件制作。柜台、货架、酒红布衬和浅色价签沿此方向调整，具体造型与比例通过部件样稿确认。最新交互采用商品下方的价签与锁左右各半，按钮造型、按压和回弹参考《Balatro》，Shader 后续另加。当前空柜阶段使用 Pixelorama 可编辑原层与无光照柜台，商品和店主分别在后续阶段验收。字体仍需用实际中文与金额样张确认。

### 像素原件拆分与交付

| 部位 | 独立制作的部件 | 交付方式 |
| --- | --- | --- |
| 后景 | 墙面、立柱与横梁、货架 | 在 Pixelorama 中分层绘制，各部件单独导出，由 Godot 摆放 |
| 柜台 | 柜身、台面、横档、木框、酒红布衬 | 保留部件边界、公共锚点和可编辑原层，按实际操作条尺寸安排空间 |
| 背景杂货 | 药瓶、药罐、草药束、木匣、麻袋、布卷货箱 | 每件独立原件，统一像素尺度，供场景组合 |
| 商品操作条 | 价签底板、开锁图标、闭锁图标、不可用态 | 原件与图标分别交付，左右各半的点击区域在 Godot 组织 |
| 共用界面 | 粉尘、设置、买卖切换、刷新、详情板与出售面板 | 按共用尺寸与边缘规范逐件制作，文字和金额由 Godot 排版 |

每件保留 `.pxo` 可编辑原件并单独导出透明 PNG。底色与对应的 OpenGL 法线分别制作，尺寸、透明边界和锚点对齐。参考图在像素软件中用于对照，最终导出取自各部件的绘制层。先用当前柜台、价签和锁的组合核对像素尺度、笔触与比例，再推进同系列部件。软件内打开原件的图层画面与 Godot 实际组合画面共同作为验收依据。

### 场景背景与右上角

- [ ] **商店背景。** 在 Pixelorama 中保留可编辑原层，概念图只用于对照构图。墙板、货架、药瓶、罐子、杂货和柜台分别交付。在 Godot 场景中逐件摆放，由程序实时打光、投影和像素化。
- [ ] **底色与法线。** 每件场景素材提供自身的底色贴图和对应的 OpenGL 法线贴图，尺寸、透明轮廓和锚点对齐。底色只记录物体本身颜色。法线描述表面朝向，墙板、货架、药瓶和柜台上的灯光与阴影由 Godot 实时计算。会投影的物件单独设置遮挡轮廓。
- [ ] **店主。** 左侧柜台后是一名绿皮肤、戴面罩的地精店主。面罩遮住脸，让玩家看不清真实长相。待机持续发笑，逐帧交付对齐的底色与法线，供 Godot 循环播放。
- [ ] **设置入口。** 商店右上角最右侧放全局设置入口。美术交付基础设置面板和它的关闭控件，关闭后返回当前商店画面。设置面板的具体选项与入口图形待确认。
- [ ] **粉尘余额。** 显示块放在设置入口左侧，由粉尘图标、余额数字和单位 `g` 组成。购买、出售或付费操作后读取实际余额。预留金额位宽，缩放后和设置入口保持间距。
- [ ] **粉尘图像。** 单独设计一枚像素图标，余额、价签与付费按钮共用。与整晶保留形态关联，让玩家在小尺寸下也能区分粉尘和整晶。图标造型、颜色和尺寸通过样稿确认。

### 商品、价签与字体

- [ ] **纹章图标。** 全套纹章重新设计，首版按实际物品名单逐枚交付。普通与传奇需要可辨认，同一枚纹章在商店、配装、战利品、结算和赎回时使用同一图标。名单见 [纹章设计文档](design/纹章设计文档.md)。
- [ ] **符文图标。** 全套符文重新设计，首版按实际物品名单逐枚交付。符文之间、符文与纹章之间要能靠轮廓或图案区分。同一枚符文在商店、配装和战利品中使用同一图标。名单随 [武器与符文设计](design/武器设计文档.md)。
- [ ] **商品位置与状态。** 按实际在售清单排展示位，保留商品详情和返回入口。能区分有货、已购买、空缺、未解锁和无法购买。药水与材料先作背景陈列。
- [ ] **商品底部价签与锁。** 按 2026-11-27 的新要求，每个商品下方使用一行操作条，左半显示粉尘图标、金额和单位 `g`，点击发起购买；右半为本件商品的锁按钮。左右按钮等宽，按钮之间保留间距。底板与文字、图标分别保留，金额由界面读取，在售、选中及不可购买时都能看清价格和对应商品。
- [ ] **按钮外形。** 参考《Balatro》的纯色切角按钮和下方深色底层，悬停压暗，按下时本体与内容一起向下位移。先验收按钮形状、比例、点击区域和开闭锁状态，Shader 后续单独加入。2026-11-27 的橙蓝试排被作者否决，原因是按钮与木柜和酒红布衬的整体氛围不契合。后续用场景已有的木褐、酒红、浅色文字与价签作同场景配色对比，按钮高度收进层板范围，颜色、切角和按下距离仍待作者视觉确认。

2026-11-27 与 Gemini 协作的空柜候选使用古铜色价签、暗铁色未锁态、酒红底金边已锁态。操作条试排为 216×38，左右各宽 104、间隔 8，放在两排内衬之间的木框范围。闭锁文案试用「已锁」。这套配色、尺寸、描边和文案为试验记录，后续视觉评审以作者重新选定的原概念图为基准。

- [ ] **统一字号与字形。** 概念图文字由图像生成工具绘制，无可核对的字体文件。用正式商品名、按钮文案、详情说明、数字和单位 `g` 做同屏样张，逐一确认字体家族、字重和字号。覆盖设置、余额、价签、购买／出售、刷新、锁定以及详情和提示文字，在实际窗口尺寸检查缺字、对齐和可读性。

字体候选待确认。可先比较同一组文字「粉尘 24 g」「购买／出售」「刷新」「锁定」「传奇纹章」。

- **缝合像素字体（Fusion Pixel Font），12 px 比例版，简体中文。** 适合先排按钮、标签和数字样张，保留清楚的像素边缘。字体采用 SIL OFL 1.1。 [字形预览](https://fusion-pixel-font.takwolf.com/) · [作者仓库及许可](https://github.com/TakWolf/fusion-pixel-font#许可证)
- **Noto Sans SC。** 无衬线简体中文字体，拿来对照设置和商品详情等较长文字的小字号可读性。字体采用 SIL OFL 1.1。 [字形预览](https://fonts.google.com/noto/specimen/Noto+Sans+SC) · [许可](https://github.com/google/fonts/blob/main/ofl/notosanssc/OFL.txt)

### 购买与出售切换

- [ ] **两套界面。** 购买在商店主画面操作。出售用从屏幕上方拉下的二级面板。两套界面共用一个购买／出售切换按钮。
- [ ] **切换按钮的购买态。** 左侧预留怪物材料图标位，具体素材待选。当前样片只显示文字。按钮主体用较大的「购买」，右下角用较小的灰色「出售」。灰色文字表示当前未选中，点击按钮可切换到出售。
- [ ] **切换按钮的出售态。** 左侧图标切换为共用的粉尘图标。按钮主体用较大的「出售」，右下角用较小的灰色「购买」。再点切换按钮，出售面板向上收起，回到购买界面。两种样式均需交付默认、悬停和按下反馈。

### 购买界面

- [ ] **店主旁的详情板。** 在店主身旁的空白区域预留一个固定位置。鼠标指向商品图标时，在该位置显示该物品的名称、详细描述和效果。指向另一件时更新同一块板；没有指向商品时收起。详情板应避开店主和商品的点击区域。
- [ ] **点击商品下方图标购买。** 每个在售商品下方的购买图标与本件商品的价签对应。点图标直接发起购买，只有触发既有的低储备提醒时才进入确认。购买完成后更新粉尘、背包和该商品状态。粉尘不足时，在对应商品处提示差额。

### 出售界面

- [ ] **下拉式二级面板。** 从购买切到出售时，面板自上向下展开，只盖住柜台商品区，显示玩家背包中的物品。店主、粉尘余额和切换按钮保留可见，切换按钮仍可操作。
- [ ] **背包类别筛选。** 面板内设置类别筛选控件，按背包物品类别筛选。美术交付默认、选中和筛选无结果的表现。筛选项用实际物品类别，具体顺序和图标待确认。
- [ ] **出售物品详情。** 选中背包物品后，显示物品名称、描述、出售报价和确认入口，沿用第 13 节的共用出售规则。详情板在出售面板内的具体位置待定。交易完成后更新背包和粉尘余额。

### 文字浮动与 UI 动效

文字浮动、控件倾转和回弹参考《Balatro》。商店先交一段包含待机、鼠标移入移出、购买／出售切换及面板开合的连续样片，用实际游戏窗口尺寸确认表现。[《Balatro》官方发售预告](https://www.youtube.com/watch?v=VUyP21iQ_-g)

- [ ] **文字浮动。** 先用当前态的大字「购买」或「出售」试做轻微上下浮动与字间错拍。小号灰字保留次要层级，价签、余额和详情正文保持易读。字体家族和字号按本节字体样张确认。
- [ ] **控件倾转与回弹。** 先用购买／出售切换按钮和商品图标试做。指向时轻抬并小幅倾转，移出时回正，按下和松开有短回弹。验收时连续扫过相邻商品，核对悬停稳定、详情对应正确、图标和可点击区域一致。
- [ ] **出售面板开合。** 保留从上方拉下、向上收起的路径，参考《Balatro》控件落位的缓动和回弹。快速来回切换时，面板、大小字和左侧图标最终都对应当前状态。
- [ ] **样片定参数。** 浮动幅度与节奏、倾转角度、回弹时长随样片确认后记录，作为共用控件动效的依据。

### 刷新、锁定与退出

- [ ] **刷新按钮。** 重新设计外形，并在点击前显示本次刷新要花的粉尘。费用数字读取实际规则。单次费用、固定或递增、刷新哪些商品位、是否限制次数，以及是否触发低储备提醒，待策划确认。
- [ ] **单件锁。** 每件在售商品下方操作条的右半为锁按钮，与左半价签等宽。点击在未锁与已锁之间切换，交付开锁、闭锁和不可用的状态。手动刷新时，锁住的商品和价签保留在原位。锁住的商品售出后，该格解除锁定。锁是否保留到下次回营及是否收费待确认。
- [ ] **低储备提醒。** 预计成交后低于下一关税额的 80% 时，NPC 在扣款前提醒，每次回营最多一次。提醒页显示预计剩余粉尘与税额。取消回到原交易，继续则执行同一笔交易。
- [ ] **退出商店。** 返回营地。现有策划规定战斗结束回营时自动刷新两个符文位。手动刷新与锁定规则确认后再补对应的界面反馈。

## 13. UI 铁匠铺、搜刮小队与出售

### 铁匠铺

- [ ] **点进入口后的界面。** 营地只设一个铁匠铺入口。进入同一界面后切换制作与强化。面板内显示可选武器或符文、详情、成本和确认结果，关闭后返回营地。

- [ ] **制作。** 已取得图纸的武器可查看成本和制作结果。确认后更新粉尘与装备库存。已制作、缺条件和库存里的成品可区分。
- [ ] **强化。** 点武器或已装符文的能力，显示可强化项、需要的强化硬币和已强化状态。成功后更新能力与硬币数量。每项只能强化一次。
- [ ] **强化硬币购买。** 在强化界面显示硬币持有量和粉尘购买入口。购买成功后更新粉尘和硬币数量。购买控件的呈现与操作细节随强化界面讨论。
### 搜刮小队

- [ ] **场景入口与内部界面。** 设计独立的入口轮廓和可赎回列表。点击遗失纹章打开详情，显示效果、价格及可用信息。确认后更新纹章列表、背包和粉尘。余额不足时保留选择，没有可赎回项时显示空状态。

### 出售
- [ ] **出售。** 常规出售与补税出售共用报价和确认。确认前标明成交金额与会失去的物品，带符文武器的报价按最终规则。确认后更新库存和粉尘，补税时同步刷新差额。

## 14. UI 战斗部署

- [ ] **需要做的界面内容。** 参战队员、允许部署格、当前部署结果、关卡主要与附加目标、采集器与地精初始状态、确认部署入口。
- [ ] **部署操作。** 选队员后显示可部署位置。点合法格更新占位。点非法格给出已占用或地形不允许等反馈，保留原来部署。允许按规则反复调整。
- [ ] **确认部署。** 条件满足时进入玩家行动与敌方预告阶段。条件未满足时指出待部署的队员或其它未达条件。部署前能否退回营地待确认。

## 15. UI 战斗操作

- [ ] **需要做的界面内容。** 8×8 盘面、单位信息、敌方攻击和出怪预告、回合与阶段、采集进度、任务目标、移动、攻击、治疗及结束回合入口。
- [ ] **查看单位和地形。** 点击单位显示生命、状态和可用行动。查看地精时读到攻击来源与目标格。查看地形时能辨认可通行、危险或特殊效果。
- [ ] **移动。** 选可行动队员后显示可移动格。点合法落点，角色移位并刷新行动状态和预告。点非法落点保持原位、保留行动，反馈阻挡、超范围或已移动等原因。
- [ ] **攻击。** 进入攻击选择后标出可选目标与适用的推拉落点。确认目标后播动作，按规则更新位置、生命、状态、占格与预告。取消目标选择时保留现有结果和行动。
- [ ] **治疗。** 可用时显示治疗对象、结果和行动消耗。成功后刷新生命和攻击或治疗的可用状态。濒死角色无法自疗，特殊恢复按已确认能力另做反馈。
- [ ] **结束回合。** 有未行动角色时给出提示，建议允许退回继续操作或确认结束。进入地精阶段后显示当前阶段，防止重复触发玩家操作。地精动作、伤害、状态和采集进度结算后更新界面。
- [ ] **战斗终止。** 胜利、全队濒死或关卡失败条件成立时进入战果结算，保留采集器和单位状态的最终结果。

## 16. UI 战果结算

- [ ] **需要做的界面内容。** 胜利或失败原因、采集完成情况、损毁情况、带回收益、奖励来源和物品、纹章经验与损失、本次税款和缴税入口。
- [ ] **战利品反馈。** 靠图标和文字区分关卡奖励、附加任务硬币与敌人掉落。直接或间接击杀的经验归属可查。达到升级时展示可选能力，具体范围随纹章专项。
- [ ] **继续。** 在战果结算界面内确认缴税或处理补税。失败也展示实际保留收益。重复点击只推进一次，缴税完成后进入营地。

## 17. UI 战果结算内的缴税与补税

- [ ] **需要做的界面内容。** 战后入账、利息、本次税额、可用积蓄、应补差额和税后余额。整晶和粉尘用同一克数口径。
- [ ] **缴税成功。** 显示本次扣除和税后余额，确认后回营地开放消费。
- [ ] **需要补税。** 显示差额和可用方式，动用积蓄或点物品出售。每次结果更新差额。关闭出售详情回补税位置，税差填平后进入缴税完成。
- [ ] **无法继续。** 当规则判定无力继续出征，显示本局结束原因并进入重新开局入口。

## 18. UI 共用交互组件与反馈

- [ ] **共用动效。** 文字浮动、控件倾转和回弹以《Balatro》为参考，先通过第 12 节的商店动效样片确认力度和节奏，再用于其它适合的共用控件。
- [ ] **基础组件。** 共用导航按钮、返回与关闭、物品卡、空槽、价格与余额、详情、状态提示、确认与取消。控件准备默认、指向、按下、选中和不可用表现。
- [ ] **鼠标反馈。** 默认建议单击选中或确认，悬停用于查看说明。确认后需要即时响应。可用范围外的操作给出具体原因。按钮文案、快捷键和取消手势在首版交互确认时一起定。
- [ ] **交易反馈。** 支付前看得到代价，完成后能核对差额。取消或失败保留原选择和数据。处理中阻止重复提交。
- [ ] **跨页反馈。** 确认框关闭后恢复到原界面和原物品。战斗返回结算时清除旧战斗选中。所有扣款、奖励和状态显示取同一份实际数据。
- [ ] **可读性。** 窗口缩放下，中文、数值、按钮热区和棋盘点击位置保持对齐。像素化 Shader 的取样范围按样片确认，界面文字、标记和数字保持清晰。
