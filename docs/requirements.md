# 参赛要求与协作分工

## 项目依据

游戏名待定，主题为守望。用户在 Obsidian 的《守望题材游戏 / 游戏设计文档》中维护玩法原稿。本页只摘录协作所需约束。用户更新规则后，再同步对应条目和测试。

- 使用 Godot 4.7.2 标准版及 GDScript。角色进入地精领地，保护采集器完成采集。地精会展示攻击意图。
- 当前玩法、参数和待确认项见[游戏设计文档](design/游戏设计文档.md)。测试时区分主策划已定规则、首轮试算参数与能力示例。

## 并行开发

| 负责端 | 当前工作与交付范围 | 验收 |
| --- | --- | --- |
| Mac | 营地数据与装备实例、配装和出征接口。下一步先核对独立装备实例、卸装与重复操作的边界测试 | 不同装备实例可分别分配给角色；同一实例不能同时装备；操作失败时原配装完好 |
| Windows | 在独立分支 codex/windows-export 做 Windows x64 可复现导出。负责 game/export_presets.cfg、必要的导出目录忽略项与 Windows 运行说明，工程入口沿用现有主场景 | 从干净检出导出到独立目录，启动导出的程序并正常退出，记录版本、指令、结果。生成的二进制保留作本机验证 |
| 双端集成 | 各自在本地验证负责的改动；合并前同步提交号和测试结果。共享入口或工程设置有变化时先协调 | 同一提交分别运行营地测试。能启动的空入口只验工程链路 |

Windows 已回报提交 7eff206 在 Windows x64 上完成无窗口导入、主场景启动与退出、营地规则测试，测试失败数为 0。导出发行版是下一项独立验证。
